## 2. 七条跨组件发现（都是新证据）

### 2.1 网络过滤是真的：`fwpkclnt.sys`

`ACE-CORE302706.sys` 导入 **`fwpkclnt.sys` 10 个函数**（WFP 内核客户端）+ `NDIS.SYS 3` + `NETIO.SYS 1`。

这是**内核级网络过滤/拦截**的结构性证据（不是用户态 hook）。配合 `HalGetBusDataByOffset`（PCI 配置空间读写），它的能力覆盖"网络栈 + 硬件总线"。

### 2.2 PCI 配置空间访问

| 组件 | 导入 |
|---|---|
| `ACE-CORE302706.sys` | `HalGetBusDataByOffset`、`HalSetBusDataByOffset` |
| `ACE-SSC-DRV64.sys` | 同上 |

可以读写 PCI 配置空间 → 能枚举/修改设备（含伪装设备、禁用 DMA 保护相关寄存器）。

### 2.3 GPU 厂商枚举

`ACE-SSC64.dll` 读：
- `SOFTWARE\Khronos\OpenCL\Vendors`
- `SOFTWARE\Khronos\Vulkan\Drivers`

→ 枚举 OpenCL/Vulkan 驱动（识别注入到 GPU 计算管线的作弊/挖矿/覆盖层）。

### 2.4 注册表回调（`CmRegisterCallbackEx`）

`ACE-BOOT.sys` 导入 `CmRegisterCallbackEx` / `CmUnRegisterCallback` / `CmCallbackGetKeyObjectID`，并对 `\Registry\Machine\SYSTEM\ControlSet%.3u\services\` 有字符串。

→ 它在**引导期就监控服务注册表的创建/修改**（防止反作弊服务被禁用/替换）。

### 2.5 远端下载端点

| 组件 | 字符串 |
|---|---|
| `ACE-Safe.dll` | `http://%s/d?dn=%s`、`http://%s/d?dn=%s&id=%s` |
| `ACE-Trace.dll` | `https://%s/%s` |
| `ACE-SSC64.dll` | `http://`、`https://` |

→ 存在按名字下载文件的通道（`dn=` 参数就是下载名），配合 `ACE-Safe.dll` 的 `tessafe.sys` 字符串，说明它还能**下发/加载额外驱动**。

### 2.6 命名管道与互斥体（IPC 面）

| 组件 | 名称 |
|---|---|
| `Uninstaller.exe` | 管道 `\\.\pipe\ebda72a0-5182-4abc-8d32-0ab95af442e3-%d`；互斥 `Global\4907db0b-5164-4f60-af3c-155e6fc47b33-` |
| `SGuard64.exe` / `SGuardUpdate64.exe` | 互斥 `Global\77775BF5-118C-42EA-8385-3800776F31BA` |
| `ACE-Service64.exe` | `\\.\pipe\`（动态名）+ `Global\Ver` |

→ 进程间用 GUID 命名的管道/互斥体协调，**名字是随机 GUID**（不是固定串），说明每次安装/会话会变化。

### 2.7 还有一个驱动：`ACE-GAME.sys`

`Uninstall64.exe` 字符串里有 `\drivers\ACE-BASE.sys` 与 `\drivers\ACE-GAME.sys`。

→ 套件里至少还有**一个未随包下发的驱动** `ACE-GAME.sys`（按需安装/下载，呼应 2.5 的下载通道）。

## 5. 方法

```powershell

python tools\ustrings.py <binary> 6            # 原始串表
```
