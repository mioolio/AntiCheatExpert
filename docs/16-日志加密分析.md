# 16 · 日志加密分析（ace-boot-*.log / ace-boot.dat）

对象：`AntiCheatExpert\ace-boot-*.log`（3 个）与 `ace-boot.dat`。
结论先说：**日志是加密的，密钥不在明文、不在注册表、不在 .dat 的明文区**，要解开必须进 `.tvm0` 追密钥派生。

---

## 1. 文件基本面

| 文件 | 大小 | 熵 | 判定 |
|---|---|---|---|
| `ace-boot-20261118-040517.log` | 1,098,431 | 7.96 | 加密 |
| `ace-boot-20261118-130717.log` | 136,560 | 7.95 | 加密 |
| `ace-boot-20261121-010547.log` | 1,044,245 | 7.97 | 加密 |
| `ace-boot.dat` | 85,016 | 7.99 | 容器（16 + 128 + 84872） |

`ace-boot.dat` 头部四个 dword 直接给出布局：

```
0x0000  DWORD  0x10        ; 头长度 16
0x0004  DWORD  0x80        ; 第二段 128 字节
0x0008  DWORD  0x90        ; 第三段起始偏移 0x90 = 0x10 + 0x80
0x000C  DWORD  0x14B88     ; 第三段长度 84,872
```

校验：`0x90 + 0x14B88 = 0x14C18 = 85,016 = 文件大小`，布局自洽。

| 区段 | 范围 | 熵 | 说明 |
|---|---|---|---|
| 头 | `0x0000..0x0010` | — | 4 个长度字段 + 4 个 dword 常量 |
| 中段 | `0x0010..0x0090` | 6.53 | 128 字节，结构化（不是纯随机），疑似密钥材料/表 |
| 载荷 | `0x0090..EOF` | 7.99 | 84,872 字节密文 |

---

## 2. 日志的密文特征

1. **三个日志共享 24 字节相同前缀**：`7b 4b 9e 5f 85 46 24 80 99 cd e1 06 27 6f 8e 45 79 bd 5e 84 9b 15 2f 67`，第 25 字节起分叉。
   → 固定 nonce / 固定密钥下加密了相同的明文头部。
2. **不是 ECB**：65,265 个 16 字节块中无任何重复（最大重数 1）。
3. **不是固定周期 XOR**：周期 16/32/64/256 的自相关率分别 0.004 / 0.004 / 0.006 / 0.005（随机水平）。
4. **不是压缩容器**：zlib（偏移 0/8/16/24/32）与 lzma 全部解压失败，`ace-boot.dat` 载荷同样失败。
5. 头部熵 7.90、可打印率 0.378 —— 与随机数据一致。

---

## 3. 已排除的密钥来源

| 假设 | 测试 | 结果 |
|---|---|---|
| 24 字节前缀是驱动里的常量 IV | 在 `ACE-BOOT.sys` 全文搜该前缀（及前 8 字节） | 0 命中 |
| 密钥在 `ACE-BOOT.sys` 明文 | 搜 `expand 32-byte k`（ChaCha）、AES S-box `63 7C 77 7B F2 6B 6F C5`、SHA-256 IV | 全部 0 命中（`expand 32-byte k` 只在 `ACE-BASE.sys` 里） |
| 密钥在注册表 | 枚举 `HKLM\SYSTEM\CurrentControlSet\Services\ACE-*` 全部值 | 只有 `Type/Start/ErrorControl/ImagePath/DisplayName` |
| `.dat` 中段是 RC4 密钥 | RC4 + 中段所有 16/32 字节窗口（步长 8） | 首选可打印率 0.415（随机水平） |
| `.dat` 中段是 ChaCha20 密钥 | ChaCha20 + 相同窗口 × nonce（全零 / 载荷前 12 字节 / 中段前 12 字节）× 计数器 0/1 | 最高 0.407（随机水平） |
| 中段是哈希后的密钥 | RC4/ChaCha20 用 `sha256(中段)` / `md5(中段)×2` | 0.415 / 0.407（随机水平） |

可打印率 0.40 左右即"解密结果仍是随机"，全部否证。

## 4. 写入路径（已定位，未走完）

`.rdata` 里的文件名格式（UTF-16）：

```
0x0606C0  "ace-boot-"                                  （路径前缀，0x3C80 引用）
0x060740  "ace-boot-%04d%02d%02d-%02d%02d%02d.log"
0x060784  "\SystemRoot\ace-boot-%04d%02d%02d-%02d%02d%02d.log"  （0x40B0 引用）
```

`ACE-BOOT.sys` 的日志入口（`.text 0x4060..0x4174`）：

```
0x40B0  lea r8, [0x60740]          ; 格式串
0x40C4  call 0x43B0                ; 格式化（sprintf 类）
0x40D9  call [IAT]                 ; RtlInitUnicodeString
0x4107  call 0x44C60               ; 打开/初始化（返回句柄）
0x412F  call 0x112F0               ; 取一个字节（al）
0x415A  call 0x486D0               ; ← 日志上下文（池标签 'jacy' = 0x6379616A）
```

实际落盘有 5 个 `ZwWriteFile` 调用点（`0x450FE`、`0x46EED`、`0x48405`、`0x48687`、`0x48BB7`）。检查 `0x450FE` 处的写助手可见：它只把 `[rsp+0x68]` 指向的缓冲按 `esi` 长度写出，**没有任何变换**。

→ 说明加密发生在**记录构造阶段**（`0x486D0` 及其调用者），不在写盘处。缓冲区在进入写助手前已经是密文。

---

## 5. 下一步（要解密必须做的三件事）

1. **从 `0x486D0` 往上追**：它是日志上下文初始化（分配 0x1400000 池、清零结构、池标签 `'jacy'`）。找到"追加一条记录"的函数，看它在格式化之后、写盘之前对缓冲做了什么。
2. **定位密钥/IV 来源**：`0x112F0` 返回的那个字节很可能是每条记录的索引或盐；真正的密钥多半来自 `.tvm0`（1.5 MB 保护段）里的派生函数。
3. **验证**：拿到密钥后，用已知的 24 字节固定前缀和 `ace-boot-<时间戳>.log` 的明文头部做已知明文校验——解出的前几个字节应可读（例如版本号或启动事件）。

工具已就绪：`trace_any.py` 可在 `.tvm0` 内折叠控制流（在 `ACE-BASE`/`ACE-CSI64` 上验证过），`diff_report.py` 可做字节级对照。

> 现状：结构层面已完全摸清（容器布局、密文特征、写入路径、排除项），**算法与密钥未取到**。这不是"没做"，是卡在保护段里，需要继续跟 `0x486D0` 的调用链。
